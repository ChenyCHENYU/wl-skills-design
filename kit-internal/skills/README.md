## 原型设计 Skill 落地计划（下一版本 v0.5.0）

> 规范 `02-prototype.md` 已完成（23 项验证清单），以下为 Skill 层落地步骤。

### 目标

让 AI 能够：
1. 根据 spec IPO 表 + 交互模式，输出符合规范的原型标注文档
2. 验证已有原型标注是否满足 D3 深度（开发就绪）
3. 输出可被 `prototype-scan`（wl-skills-kit）直接消费的格式

## 增量设计支持（v0.6.0 规划）

> 当前 Skill 更适合「从零开始」的场景。真实项目中设计是增量的。

### 目标

各 Skill 增加增量模式，支持：
- 在已有设计文档上追加/修改（不重新生成全文）
- 自动检测已有内容，避免重复生成
- 变更影响分析（改了 spec 的某个字段，哪些 DB/接口/原型需要同步更新）

### 涉及的 Skill

| Skill | 增量场景 |
|-------|---------|
| spec | 新增一个功能点到已有模块 |
| database | 给已有表加字段 / 新增关联表 |
| api | 给已有模块加接口 / 修改接口字段 |
| prototype | 给已有页面加按钮/字段 |
| glossary | 新增词条（已支持，天然增量） |

## 设计产物版本追踪（v0.6.0 规划）

### 目标

在生成的设计文档头部自动注入元信息：

```markdown
<!-- generated by wl-skills-design v0.4.2, skill: database/v1.0, date: 2026-06-01 -->
```

### 用途

- 集成评审时检测各产物是否由同一版本规范生成
- 追溯某份设计文档是哪个版本的规范产出的
- `update` 时判断哪些产物需要按新规范重新验证

## 错误恢复机制（v0.6.0 规划）

### 目标

当 AI 执行 Skill 失败时，提供统一的恢复路径：

| 失败场景 | 当前行为 | 改进后行为 |
|---------|---------|-----------|
| spec 文件不存在 | 报错 | 引导用户先创建 spec，给出 `create-spec-section` 命令 |
| 跨文件联动对端缺失 | 标「暂挂」 | 标暂挂 + 给出创建对端的具体命令 |
| 字段在词典中找不到 | 标不一致 | 提示「是否要将此字段登记到词典？」 |
| 验证项全部失败 | 逐项列出 | 按 P0→P1→P2 排序，给出修复顺序建议 |

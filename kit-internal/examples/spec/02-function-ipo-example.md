### 示例二：状态机功能（PMPM007 炼钢计划确认/下发）

> **场景说明**：炼钢计划有完整的状态流转。计划员起草，提交后进入审批，审批通过后下发到各工序。体现：状态约束在输入列、状态流转在Process列、界面刷新在Output列。

**状态流转图**：
```
草稿(DRAFT) → 待审核(PENDING) → 已确认(CONFIRMED) → 已下发(ISSUED)
                  ↓（驳回）
              草稿(DRAFT)（重新编辑后可再次提交）
```

**(1) 列表页**

| 序号 | 按钮/功能 | 输入（Input）| 处理逻辑（Process）| 输出（Output）|
|------|-----------|-------------|-------------------|--------------| 
| 1 | 【搜索】按钮 | 计划月份（必选）、炉号（可选）、状态（可选）| 按条件过滤炼钢计划，按计划日期升序排列；分页每页50条 | 列表刷新，展示命中记录及总数 |
| 2 | 【新增】按钮 | / | 初始化空白表单，计划日期默认当天 | 打开【新增炼钢计划弹窗】|
| 3 | 【修改】按钮 | 选中行（状态须为「草稿」）| (1)校验状态为 DRAFT；(2)读取该行全部字段 | 允许：打开【修改弹窗】字段已回填；不允许：Toast提示「仅草稿状态允许修改」|
| 4 | 【提交审核】按钮 | 选中行（状态须为「草稿」）| (1)校验状态为 DRAFT；(2)更新 status → PENDING；(3)写入 submit_time/submit_by；(4)创建审批任务，通知审核人 | Toast提示「已提交审核」；行状态刷新为「待审核」|
| 5 | 【审核通过】按钮 | 选中行（状态为「待审核」，当前用户须有审核权限）| (1)校验状态为 PENDING；(2)校验当前用户角色；(3)更新 status → CONFIRMED；(4)写入 confirm_time/confirm_by | Toast提示「审核通过」；行状态刷新为「已确认」|
| 6 | 【驳回】按钮 | 选中行（状态为「待审核」）+ 驳回意见（必填）| (1)校验状态为 PENDING；(2)更新 status → DRAFT；(3)写入驳回意见与时间；(4)通知原提交人 | 弹出驳回意见输入框；提交后：Toast提示「已驳回」，行状态刷新为「草稿」|
| 7 | 【下发】按钮 | 选中行（状态须为「已确认」）| (1)校验状态为 CONFIRMED；(2)更新 status → ISSUED；(3)推送计划数据至各工序接口 | Toast提示「下发成功」；行状态刷新为「已下发」|
| 8 | 【撤销下发】按钮 | 选中行（状态须为「已下发」，且无实绩数据）| (1)校验状态为 ISSUED；(2)校验无实绩记录；(3)更新 status → CONFIRMED | 允许：Toast提示「撤销成功」，状态回退；不允许：Toast提示「已有实绩数据，不允许撤销」|
| 9 | 【导出】按钮 | / | 将当前查询结果全量按Excel模板序列化 | 触发文件下载；文件名：炼钢计划_{当前日期}.xlsx |

## 格式规范说明（AI 参考）

### 节编号格式

```
4.x.4.z    【功能编码】功能名称        ← 功能节
4.x.4.z.1  画面逻辑（原型）            ← 画面节
4.x.4.z.2  处理逻辑（IPO）             ← IPO节
```

### IPO 表5列定义

| 列名 | 职责 | 填写规则 |
|------|------|---------|
| 序号 | 行号 | 从1递增，列表页与新增/修改页分开编号 |
| 按钮/功能 | 触发动作 | `【按钮名】按钮` 或 `[页面名]输入字段信息` |
| 输入（Input）| 前置输入 | 无输入填 `/`；有输入逐一列出字段/条件 |
| 处理逻辑（Process）| **后端/数据库操作** | 数据校验 + 数据处理（写入/更新/触发事件）|
| 输出（Output）| **前端UI反馈** | Toast / 弹窗行为 / 页面跳转 / 文件下载 |

### 确认按钮 Process + Output 写法（三段式）

**Process 列**：
```
**(一)数据校验**：
(1) {必填项校验}；未通过提示「{提示语}」
(2) {格式/范围校验}
(3) {业务唯一性校验}
(4) {跨字段业务规则}

**(二)数据处理**（校验通过后执行）：
数据变化：{写入/更新哪张表，哪些字段，状态初始值}
触发事件：{下游计算/消息通知/状态流转；无则写"无"}
```

**Output 列**：
```
(1)校验失败：Toast提示「{错误信息}」，高亮异常字段，弹窗保持打开
(2)校验通过：关闭【{弹窗/页面名称}】，列表刷新，Toast提示「{成功提示}」
```

> 纯查询/跳转类按钮（如【搜索】【取消】【导出】）**不需要**两段式，Output列直接描述UI反馈即可。

### 输入列的填写规则

- 有明确输入值 → 列出具体字段及必填/选填说明
- 无输入 → 填「/」
- 选中行 → 填「选中行」（表示需要先选择列表中一行）
- 字段行的 Output → 填「—」（字段行无直接输出，由确认按钮统一反馈）

### 常见字段类型标注

| 字段类型 | 标注方式 | 示例 |
|---------|---------|------|
| 枚举下拉 | `（下拉）` | 钢种编号（下拉）|
| 日期 | `（日期选择器）` | 计划日期（日期选择器）|
| 数字 | 说明精度/范围 | 比例（%，0～100，精度2位）|
| 自动带出 | `（自动带出）` | 钢种名称（自动带出）|
| 多选 | `（多选）` | 标签（多选）|
4.x.4.z.2  处理逻辑（IPO）             ← IPO节
```

### IPO 表分页规则

- 同一功能有多个独立画面（列表/新增/修改/查看），**每个画面单独标注 `(1)/(2)/(3)...`**
- 每个画面用单独的 `| 序号 | 按钮/功能 | 输入 | 处理逻辑 |` 表格

### 处理逻辑四段式（确认/提交类按钮必须使用）

```
**(一)数据校验**：
(1) 检查必填项：[字段列表]
(2) [业务规则]

**(二)处理逻辑**：
数据变化：[数据库操作说明]
触发事件：[联动操作、消息通知、状态流转等]
界面动作：[前端 UI 反馈，如关闭弹窗、刷新列表、Toast 提示]
```

> 纯查询/跳转类按钮（如【搜索】【取消】【导出】）**不需要**四段式，直接描述行为即可。

### 输入列的填写规则

- 有明确输入值 → 列出具体字段及必填/选填说明
- 无输入 → 填「/」
- 选中行 → 填「选中行」（表示需要先选择列表中一行）

## 格式说明（供 AI 参考）

### 列定义

| 列名 | 说明 |
|------|------|
| 流程编码 | 格式：`[子模块代码]-A-[NN]` |
| 流程名称 | 对应 4.x.2.y 中的流程名称 |
| 活动编码 | 格式：`[流程编码]-E-[NN]` |
| 活动名称 | 对应活动说明表中的活动名称 |
| 对应作业画面 | 画面展示名称（即用户在系统中看到的菜单/页面标题）|
| 所属功能编码 | 对应 4.x.4.z 的功能编码（如 PMMB001）|

### 多对多关系处理

- **一个活动对应多个画面**：重复该活动行，每行填一个画面（如 PMMB-A-01-E-01 对应3行）
- **多个活动对应同一画面**：重复该画面行（如 PMMB012 出现3次，分别是设定/审核/修改状态）
- **无对应画面的活动**（纯线下操作）：在对应画面列填「/」

### 表格与其他章节的联系

```
4.x.1 流程清单           ← 列出流程编码和名称（汇总）
4.x.2 流程说明           ← 每条流程的活动说明表（详细）
4.x.3 流程画面对照表      ← 活动 ↔ 画面 的对应关系（本表）
4.x.4 功能设计（IPO）     ← 每个画面的详细 IPO 表
```

三张表要保持一致：
- 对照表中引用的活动编码必须出现在流程说明的活动说明表中
- 对照表中引用的功能编码必须出现在 4.x.4 功能设计中

### 生成本表的建议顺序

1. 先写 4.x.2 流程说明（活动说明表），确定所有活动编码
2. 再写 4.x.4 功能设计列表，确定所有功能编码
3. 最后写 4.x.3 对照表（根据前两步的数据填充，不会遗漏）
